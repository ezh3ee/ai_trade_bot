# AI Trading Bot — MVP

Telegram-бот, который следит за BTCUSDT на линейных фьючерсах Bybit,
ловит технические события, спрашивает LLM и присылает разбор в Telegram.

**Бот не открывает и не закрывает сделки.** Никогда. Это только анализ.

---

## Быстрый старт

```powershell
bun install

Copy-Item .env.example .env        # Windows
Copy-Item prompts.example.yml prompts.yml

# заполнить 5 полей в .env, потом:
bun run smoke        # проверить, что LLM отвечает
bun run start        # запустить бота
bun run check        # типы + тесты
```

## Команды бота в Telegram

| Команда | Что делает |
|---|---|
| `/status` | бот жив, цена, сделки, последний сигнал, лимит |
| `/mode expert` | короткий разбор |
| `/mode beginner` | подробное объяснение |
| `/pause` | перестать присылать сигналы |
| `/resume` | снова присылать |

Писать боту можно **только** с `TELEGRAM_ADMIN_CHAT_ID`. Команды от чужих чатов
молча игнорируются.

## Что куда уходит

| Что | Telegram | Консоль |
|---|---|---|
| **LONG / SHORT** | да | да |
| **WAIT** | **нет** | да |
| сработавший триггер | нет | да |
| пульс раз в минуту | нет | да |
| **ошибка** | да | да |

WAIT в Telegram не отправляется намеренно: таких сообщений большинство, они
приходят без звука и просто забивают чат. Полный текст WAIT — на `LOG_LEVEL=debug`.

Ошибки в Telegram уходят обязательно (иначе бот молча сломается), но не чаще
трёх в час: сломанный Telegram иначе заспамит сам себя.

## Проверка без Телеграма

`TELEGRAM_DRY_RUN=true` — бот печатает сообщения в консоль вместо отправки.
Удобно, если VPN недоступен или не хочется тратить токены на проверку доставки.

## Что заполнить в `.env`

| Поле | Что это |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен от @BotFather |
| `TELEGRAM_ADMIN_CHAT_ID` | твой id (узнать: @userinfobot) |
| `LLM_BASE_URL` | любой OpenAI-совместимый API |
| `LLM_API_KEY` | ключ этого API |
| `LLM_MODEL` | имя модели у провайдера |

Примеры `LLM_BASE_URL`:

```
DeepSeek    https://api.deepseek.com/v1
xAI Grok    https://api.x.ai/v1
OpenRouter  https://openrouter.ai/api/v1
Ollama      http://localhost:11434/v1
```

Провайдер не зашит в коде. Смена API = смена трёх строк в `.env`.

## Структура

```
src/
  config/      Zod-схема .env, логгер
  market/      триггеры, окно сделок, deque, движок
  bybit/       WebSocket, разбор сообщений, тикер
  ai/          контекст, шаблон, промпты, провайдер, схема ответа
  telegram/    отправка, формат expert/beginner
  app/         оркестратор — связывает всё
  *.module.ts  сборка Nest, логики в них нет
```

**Логика не знает о Nest.** `TriggerEngine`, `TradeWindow`, `BybitWsClient`,
`AnalysisOrchestrator` — обычные классы без декораторов. Nest их создаёт и
передаёт. Их можно тестировать и переносить без фреймворка.

## Правила, которые нельзя нарушать

**Проверки триггеров — на каждом тике, не по таймеру.**
§9B ищет *пересечение* уровня — это событие, а не состояние. Проверка раз в
секунду потеряла бы пробой, случившийся и откатившийся внутри одной секунды.
Ограничиваются **события** (вызов LLM, отправка), а не **проверки**.

**Кулдаун не заменяет детекцию события.** §9 прямо это требует, иначе бот
долбит запросами на каждый тик.

**Неизвестная переменная в шаблоне — ошибка, а не мусор.** Опечатка
`{{market.prcie}}` валит приложение в момент старта, а не через неделю в
проде. Неизвестные *данные* (Bybit не прислал funding) — не ошибка, печатается
«—».

## Промпты

`prompts.yml` — два набора: `expert` и `beginner`. Каждый с `system` и `user`.

Тикер туда не пишется — он подставляется из конфигурации.

Список доступных переменных: `CONTEXT_FIELDS` в `src/ai/template.ts`.

## Тесты

170 тестов. Логика проверяется без сети, без ключей и без поднятия Nest.

Отдельно: `test/market/reference.ts` — намеренно медленный эталон, написанный
через `filter`/`reduce`. `differential.test.ts` гоняет его против оптимизированной
версии на случайных данных и требует полного совпадения. Если быстрый код
соврёт — тест упадёт.

## Производительность

`bun run bench`, установившийся режим, окно 11 минут:

| сделок/сек | версия | на сделку | загрузка loop | худший тик |
|---|---|---|---|---|
| 1000/с | оптимизированная | 0.57 мкс | 0.06 % | 39 мкс |
| 1000/с | наивная | 1214 мкс | 121 % | ~4200 мкс |

Наивная версия при 1000 сделок/сек потребляет больше одного ядра и не успевает
за рынком. Отдельный её тик — 4 мс, это видимая заморозка.

## Что за файлы в src/telegram

```
commands.ts        разбор команд и проверка доступа. Чистые функции,
                   тестируются без сети и без grammY
status.ts          форматирование /status и строки-пульса
telegram-bot.ts    сам бот на grammY + разделение каналов notify/logOnly/reportError
telegram.module.ts сборка Nest и подписка на команды
format.ts          тексты сообщений expert и beginner
```

Логика команд отделена от grammY специально: команды проверяются обычными
тестами, сеть для этого не нужна.

## Чего ещё нет

По ТЗ не реализовано: база данных (Prisma), команда `/position` (нужна, только
если торгуешь руками через Bybit), свечи с REST, Docker, режим ответа
per-user с хранением в базе. Режим сейчас переключается командой `/mode`
в памяти процесса и теряется при перезапуске.

## ⚠ Telegram может быть заблокирован

При проверке из одной сети `api.telegram.org` резолвился по DNS, но TCP 443 не
проходил, тогда как Bybit был доступен. Если сообщения не доходят — нужен VPN.
На всякий случай есть `TELEGRAM_DRY_RUN=true`.

## Ответственность

Бот не является инвестиционной рекомендацией. Уверенность в ответе модели — это
её самооценка, а не вероятность прибыли. Если данных мало, правильный ответ —
`WAIT`, и бот так и отвечает.
